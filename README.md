# iCloudの写真を、Windowsのフォルダへ

自分のiCloud写真（iPhoneの中にあるファイルではなく、iCloud上の写真と動画）を、Windowsのフォルダに移すための個人用アプリです。家族のアカウントを、その人の前で使う想定です。公開配布用ではありません。

写真は日付ごとに並びます。選んで、エクスプローラーのフォルダへドラッグするか、「フォルダに保存」を押します。届くファイルは、もともとの名前の原本です（`IMG_0001.HEIC` や `IMG_0001.MOV` など）。

## この作り方にした理由

Appleには、個人のパソコンからiCloud写真を取る公式のAPIがありません。そこで、実績のあるオープンソース [icloudpd](https://github.com/icloud-photos-downloader/icloud_photos_downloader) 1.33以降と同じ部品（`pyicloud_ipd`）を使います。高度なデータ保護（ADP）のアカウントも、icloudpd の `--adp-web-access` と同じ手順（`request_pcs_consent`）で扱います。

画面は Python と Qt（PySide6）です。Windowsでは、ドロップされるまで原本を渡せるよう、エクスプローラーが理解する OLE（`FileGroupDescriptorW` と `FileContents`）でドラッグします。すでに手元にあるファイルは、通常のファイルコピー（`CF_HDROP`）にもします。

.NET の方が OLE は書きやすいのですが、icloudpd の部品をそのまま使えません。Electron は容量が大きく、フォルダへのドロップが不安定です。そのため Python + Qt にしました。

配布は、インストールしないフォルダ一式です。exe を一つに固める方式は、起動のたびに一時フォルダへ展開します。学校のパソコンでは一時フォルダが制限されていることがあるので、展開しない形にしています。

## 学校のパソコンで使う

このアプリは、次の前提で動きます。

- インストール作業は不要です。ZIPを展開して `IcloudDrop.exe` をダブルクリックします。
- 管理者権限も、UACの「はい」も要りません。
- アプリ自身はレジストリに設定を書きません。設定・クッキー・キャッシュは、exeの隣の `data` フォルダです。
- Python や .NET を別途入れる必要はありません。必要なものはフォルダに入っています。
- パスワードは、保存すると選んだときだけ、そのWindowsユーザー専用の保護（DPAPI）で `data` の中にしまいます。資格情報マネージャーは、それが使えないときの予備です。どちらも使えないときは保存せず、次回もパスワードを入力します。平文では書きません。

フォルダごと、USBメモリやデスクトップに置いてください。`IcloudDrop.exe` だけを別の場所に移すと動きません。

## 入れ方

1. `IcloudDrop-portable.zip` を、デスクトップやUSBメモリにコピーします。
2. 右クリックして「すべて展開」します。展開先のフォルダごと残します。
3. 中の `IcloudDrop.exe` をダブルクリックします。

初回のWindowsは、見慣れないアプリだと知らせます。これは署名をしていないためです。後述の「SmartScreen」を見てください。

## 最初のサインイン

1. Apple ID とパスワードを入力します。
2. 信頼できるデバイス（ふだん使っているiPhoneなど）に、6桁のコードが届きます。そのコードを入力します。
3. 「パスワードをこのパソコンに保存する」にチェックすると、次回からパスワード欄が埋まります。チェックしなければ、パスワードは記憶しません。
4. サインインが成功すると、クッキーを `data\session` に保存します。Appleの期限（いまはおよそ2か月）までは、毎回コードを聞かれにくくなります。期限が切れたら、またコードを入力します。

練習だけしたいときは「デモで試す」を押します。サンプル写真が開き、iCloudには繋がりません。練習用のサインインでは、パスワードは `wrong` 以外、確認コードは `123456` です。

自分でソースから試すとき:

```powershell
python -m icloud_drop --demo
python -m icloud_drop --mock
python -m icloud_drop --self-check
```

`--self-check` は画面を出さず、保存とドラッグ用データの組み立てだけ確認して終了します。

## 写真の取り込み

- クリックで1枚、Ctrlを押しながらで追加、Shiftで範囲、`Ctrl+A` または「すべて選択」で表示中の全部です。
- 「日付を指定」をオンにして「この期間を選択」を押すと、その期間だけが選ばれます。
- 「写真」「動画」で絞り込めます。
- 選んだ写真を、エクスプローラーやデスクトップへドラッグします。届くのは原本です。Live Photoは、写真と対の `.MOV` も一緒に渡します。
- ドラッグでは HEIC を JPEG にしません。変換したいときは「フォルダに保存」を使い、「HEICをJPEGにする」にチェックします。
- 「フォルダに保存」は、選んだものだけを保存します。何も選んでいないときは、表示中の全部を保存するか聞いてきます。
- 同じ名前で同じ大きさのファイルが既にあるときは、取り直しません。途中まで書いたファイルは、続きから書きます。中止しても、終わったファイルは残ります。
- 保存先には `icloud-drop-manifest.json` ができます。どれを保存し終わったかの記録です。消しても、同じ大きさのファイルがあれば飛ばします。
- iCloud上の写真は消しません。このアプリに削除機能はありません。

枚数が多いときは、ドロップしたあとに1件ずつ原本を取ります。状態は小さな窓に出ます。失敗した件は `data\logs\app.log` に残ります。

## 高度なデータ保護（ADP）

高度なデータ保護をオンにしていると、ふつうのサインインだけでは写真を読めず、`ACCESS_DENIED` になります。そのときは画面に、次の案内が出ます。

1. iPhoneで「設定 → 一番上の自分の名前 → iCloud → Web上のiCloudデータにアクセス」をオンにする。
2. このアプリのサインイン画面で「高度なデータ保護のWebアクセスを使う」にチェックを入れる。
3. もう一度サインインする。初回はiPhoneに「許可」が届くので、2分以内に押す。

この手順は、icloudpd の `--adp-web-access` と同じです。許可はiPhone側の操作なので、アプリから勝手には通りません。

中国本土の iCloud（icloud.com.cn）を使う場合だけ、「中国本土のiCloudを使う」にチェックします。

## データが置かれる場所

exeの隣です。

```text
IcloudDrop.exe
portable.txt
data\
  settings.json    設定。パスワードは入れません
  session\         サインインのクッキー
  secrets\         保存すると選んだパスワード（暗号化）
  cache\           ドラッグ用の原本
  logs\app.log
```

exeの隣に書けないときだけ、`%LOCALAPPDATA%\IcloudDrop` に退避します。そのときは画面のログに残します。場所を指定したいときは、環境変数 `ICLOUD_DROP_DATA` にフォルダを指定して起動します。

## Windows版をダウンロードする

このアプリの置き場所は Origin です。Origin 自体には Windows でビルドする機械がありません。つながる CI（Depot や EngFlow）も Linux だけです。手元の Windows がなくても作れるように、GitHub Actions の Windows 機械で zip を作り、決まったアドレスに置く設定を入れてあります。

いまのコードは GitHub にはまだありません。GitHub のリポジトリをこちらから新しく作ることはしていません。次の一度だけ、自分の GitHub（Cursor に接続済みの `daichingale`）で空のリポジトリを作り、このコードを送ってください。

1. https://github.com/new を開く。名前は例えば `icloud-drop`。README も .gitignore も追加しない（空のまま）。
2. 誰でもリンクだけで受け取れるようにするなら Public。自分だけなら Private。Private のファイルは、ブラウザで GitHub にログインしていないとダウンロードできません。
3. このフォルダで、次を実行する。`<名前>` は作ったリポジトリ名です。

```powershell
git remote add github https://github.com/daichingale/<名前>.git
git push github main
```

送ったあと、GitHub の Actions が Windows 上でビルドします。終わると、次のアドレスのファイルが差し替わります。

```text
https://github.com/daichingale/<名前>/releases/download/windows/IcloudDrop-portable.zip
```

進行はリポジトリの Actions タブで見られます。失敗したときは、そのログを開きます。もう一度だけ走らせたいときは、Actions の「Windows portable」を選び、「Run workflow」を押します。

## 自分でWindows版を作る

手元に Windows があるときの手順です。Python 3.12 を、ユーザー権限で入れておきます（「すべてのユーザーにインストール」は不要です）。

```powershell
py -3.12 -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install -e ".[icloud,keyring,dev]" pyinstaller
powershell -ExecutionPolicy Bypass -File .\scripts\build_windows.ps1
```

`py` が無いときは、1行目を `python -m venv .venv` にします。

できあがりは `dist\IcloudDrop-portable.zip` です。中は `IcloudDrop\IcloudDrop.exe` と、同じフォルダのファイル一式です。テストもこのスクリプトの中で実行します。GitHub に送った場合は、上の「Windows版をダウンロードする」のアドレスから同じ zip を取れます。

ソースのまま動かすとき（開発用）:

```powershell
.\.venv\Scripts\Activate.ps1
python -m pip install -e ".[dev]"
python -m pytest
python -m icloud_drop --demo
```

本物のiCloudに繋ぐには `pip install -e ".[icloud,keyring]"` も要ります。画面のデモとテストは、iCloudがなくても動きます。

## うまくいかないとき

**「WindowsによってPCが保護されました」（SmartScreen）**  
署名のないexeなので出ます。個人で作ったものです。「詳細情報」を押し、「実行」を押します。ZIPをダウンロードした直後は、exeを右クリックして「プロパティ」を開き、下の「許可する」にチェックを入れてから起動する方法もあります。これはWindowsがそのファイルに付けた印を外す操作で、アプリがレジストリを書くものではありません。

**何も起きない、または「このアプリは管理者によってブロックされています」**  
AppLocker や、学校の許可リストで止められています。このアプリから回避する方法はありません。情報の先生に、展開したフォルダの実行を許可してもらう必要があります。すでに実行が許されている場所（一部の学校ではUSBや自分のデスクトップ）へフォルダごと移して試す、という相談はできます。

**ウイルス対策が消した**  
PyInstallerで固めたexeは、誤検知されることがあります。自宅のWindowsで上の手順どおり自分でビルドし、そのフォルダをUSBで持っていくと、ダウンロードしたexeより通りやすいことがあります。それでも消される場合は、対策ソフトの除外を頼むしかありません。

**サインインできない**  
Apple IDとパスワードを確認します。コードは6桁です。何度も間違えると、Apple側でしばらく止められます。`data\session` を消してから、もう一度最初からサインインすると直ることがあります。

**写真の一覧で「アクセスできません」**  
上の「高度なデータ保護」を読んでください。Webアクセスをオフにしたままでは読めません。

**ドラッグしてもフォルダに入らない**  
「フォルダに保存」を使ってください。ドラッグはWindowsのエクスプローラー向けです。保存の方は同じ原本を、選んだフォルダに書きます。

**HEICが開かない**  
Windowsの「フォト」がHEICに対応していないことがあります。「HEICをJPEGにする」にチェックして保存すると、JPEGで書き出します。ドラッグしたファイルは原本のHEICのままです。

**セキュリティキー（YubiKeyなど）だけのアカウント**  
「セキュリティキーで承認」を押して、キーを挿して触れます。学校のパソコンでUSBキーが禁止されているときは、6桁のコードが使える設定が必要です。

## ここで確認できたこと、実機でまだ必要なこと

開発に使った環境はLinuxです。本物のiCloudアカウントも、Windowsも、ここでは使っていません。

自動テストで確認したこと:

- クリック、Ctrl、Shift、全選択、日付の範囲選択
- 写真と動画の絞り込み、日付ごとのまとまり、名前順
- 保存のスキップ、途中からの再開、Live Photoの対の動画、同じファイル名が重なったときの別名
- HEICという名前でも中身がJPEGならJPEGとして書き出せること。壊れたHEICは失敗すること
- パスワードは、頼んだときだけ保存し、平文では残さないこと。保存先が両方だめなら、保存せずに先へ進むこと
- 設定ファイルにパスワードを書かないこと
- exeの隣にデータを置くこと。書けないときはユーザーのフォルダへ退避すること
- 練習用のサインイン（コード、デバイスでの許可、高度なデータ保護で拒否される場合、セキュリティキー）
- 1000件分の、エクスプローラー向けファイル一覧の組み立て
- 画面を表示しないモードで、デモの一覧、複数列のサムネイル、動画だけの絞り込み、フォルダへの保存と2回目のスキップ

まだ、本物のWindowsパソコンと本物のiCloudで確認が必要なこと:

- エクスプローラーへの実際のドロップ（OLE）
- Appleの2ファクタと、高度なデータ保護の「許可」通知
- DPAPIでのパスワード保存
- SmartScreenや学校のAppLockerで、フォルダごと起動できるか
- 数千枚のときに、時間がかかりすぎたり、Appleに一時的に止められたりしないか

`python -m icloud_drop --self-check` は、配布したフォルダの中でも、画面の手前でロジックだけ確認できます。
